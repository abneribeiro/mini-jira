# **architecture**

the layering, package layout, engineering decisions and known limitations. the design rationale (data model, migrations, auth) lives in [minijira.md](../minijira.md).

## **layering**

```text
HTTP request
    |
    v
Handler      net/http + chi. Decodes input, maps domain errors to status codes.
    |        Knows nothing about SQL.
    v
Service      Business rules and validation. Knows nothing about net/http.
    |
    v
Repository   All SQL. Authorization is part of the query (authz.Scope).
    |        Knows nothing about HTTP.
    v
PostgreSQL   Constraints (PK, FK, UNIQUE, CHECK, NOT NULL) are the last line of defence.
```

Each domain (`user`, `project`, `task`, `auth`) is one package holding its model, repository, service and handler. Cross-cutting concerns live in small packages:

| Package | Responsibility |
|---|---|
| `internal/authz` | `Scope{UserID, IsAdmin}`: who is calling, passed from middleware down to SQL |
| `internal/database` | pgx pool setup; translates SQLSTATE `23505` / `23503` into checks the repositories turn into domain errors |
| `internal/httpx` | JSON responses, the single error envelope, strict capped body decoding, path UUID and pagination parsing |
| `internal/middleware` | JWT authentication, admin guard, rate limiting, structured request logs, metrics |
| `internal/server` | Router assembly, `/health`, `/livez`, and the private metrics router |
| `internal/jwt` | HS256 access token issue and validation |
| `internal/metrics` | Prometheus collectors and the periodic gauge collector |

## **engineering decisions**

- **UUID v7 identifiers, generated by the service.** IDs are not guessable like a sequence, yet stay roughly time-ordered for index locality. The ID exists before the row is written.
- **Explicit SQL with pgx/v5, no ORM.** Every query is visible, parameterised and reviewed with its indexes. Partial updates build their `SET` clause in a pure function that is unit tested.
- **Authorization inside the query.** Repositories receive an `authz.Scope` and filter with `WHERE owner_id = $n OR $isAdmin`. Ownership checks and writes happen in one statement, so there is no read-then-decide window. Moving a task checks the destination project in the same `UPDATE`.
- **Rotating refresh tokens with reuse detection.** Login returns a 15-minute JWT and a 30-day opaque refresh token. Each refresh revokes the presented token and issues the next one in the same family. Presenting an already rotated token means it leaked, so the whole family is revoked. Only the SHA-256 of a refresh token is stored.
- **Password change ends every session.** Updating the password through `PUT /users/{id}` revokes all of that user's refresh tokens.
- **Timing equalisation on login.** When the e-mail is unknown, the password is still compared against a dummy bcrypt hash, so response time does not reveal which e-mails are registered. Both failures return the same `401 invalid_credentials`.
- **Infrastructure errors are never credential errors.** A database outage during login is a `500`, logged in full, not a misleading `401`.
- **Private metrics listener.** `/metrics` is served on `METRICS_PORT` (9091), which Compose does not publish. The public port answers `404` for it.
- **Rate limiting that cannot be spoofed by default.** Login and refresh are throttled per client IP with separate token buckets. Proxy headers (`X-Forwarded-For`, `X-Real-IP`) are honoured only when `TRUST_PROXY_HEADERS=true`.
- **One error envelope everywhere**, including unknown routes (`404 not_found`) and wrong methods (`405 method_not_allowed`).
- **Migrations are a separate step.** `cmd/migrate` runs as a one-shot container before the API starts; the API never changes the schema on boot.

## **stack and layout**

Go 1.27, chi v5, pgx v5, goose v3, golang-jwt v5, bcrypt, Prometheus client, PostgreSQL 18, Prometheus, Grafana, Docker Compose.

```text
mini-jira/
  cmd/
    api/                 HTTP server; also `api healthcheck` for the container probe
    migrate/             goose runner: up | down | status | version
  internal/
    auth/                login, refresh rotation, logout, refresh-token repository
    authz/               Scope and roles
    config/              environment configuration
    database/            pgx pool, SQLSTATE helpers
    httpx/               JSON, error envelope, path and pagination helpers
      httpxtest/         error envelope assertion for handler tests
    jwt/                 access tokens
    metrics/             Prometheus collectors
    middleware/          auth, caller scope, admin guard, rate limit, logging, metrics
    migrations/          versioned SQL, embedded with go:embed
    project/             projects domain
    server/              router wiring and probes
    task/                tasks domain
    testdb/              integration test database and user seeding
    user/                users domain
  grafana/               provisioned datasource and dashboard
  prometheus/            scrape configuration
  scripts/smoke.sh       end-to-end smoke test
  Dockerfile             multi-stage, distroless, non-root
  docker-compose.yml
  Makefile
```

## **known limitations and trade-offs**

- **Stolen access tokens stay valid for up to 15 minutes.** This applies even after a logout, a password change or a role change. Immediate revocation would need a per-request lookup, which gives up the stateless JWT. Refresh tokens are revoked immediately.
- **Changing the password does not ask for the current password.** A valid access token is enough. Requiring it would be a stronger flow and a contract change.
- **The rate limiter is per process.** With several replicas the effective limit multiplies; a shared store such as Redis would be needed.
- **No JWT key rotation.** Changing `JWT_SECRET` invalidates every access token at once.
- **Every member can read the user list**, including names and e-mails, so that tasks can be assigned. A stricter deployment would restrict this.
- **Any user can be an assignee.** Assigning a task does not give the assignee access to it, because access follows project ownership only.
- **No CORS, no audit log.** Role changes and deletions are visible only in the application logs.
- **Offset pagination.** It is simple and bounded at 200 rows per page, but deep offsets get slower; keyset pagination would scale better.
- **chi's timeout and recoverer middleware** answer `504` and `500` without the JSON envelope in the rare cases they fire.
