# mini-jira

A small project and task tracker exposed as a REST API in Go. It is deliberately compact, but built the way a production service should be: strict layering, SQL-level authorization, revocable sessions, structured logs, Prometheus metrics, and a test suite that runs against a real PostgreSQL.

The design rationale (data model, migrations, authentication and authorization design) lives in [minijira.md](minijira.md). This README covers how to run it, how to use it and how it is tested.

## Architecture

```text
HTTP request
    |
    v
Handler      net/http + chi. Decodes input, maps domain errors to status codes.
    |        Knows nothing about SQL.
    v
Service      Business rules and validation. Knows nothing about net/http.
    |
    v
Repository   All SQL. Authorization is part of the query (authz.Scope).
    |        Knows nothing about HTTP.
    v
PostgreSQL   Constraints (PK, FK, UNIQUE, CHECK, NOT NULL) are the last line of defence.
```

Each domain (`user`, `project`, `task`, `auth`) is one package holding its model, repository, service and handler. Cross-cutting concerns live in small packages:

| Package | Responsibility |
|---|---|
| `internal/authz` | `Scope{UserID, IsAdmin}`: who is calling, passed from middleware down to SQL |
| `internal/database` | pgx pool setup; translates SQLSTATE `23505` / `23503` into checks the repositories turn into domain errors |
| `internal/httpx` | JSON responses, the single error envelope, strict capped body decoding, path UUID and pagination parsing |
| `internal/middleware` | JWT authentication, admin guard, rate limiting, structured request logs, metrics |
| `internal/server` | Router assembly, `/health`, `/livez`, and the private metrics router |
| `internal/jwt` | HS256 access token issue and validation |
| `internal/metrics` | Prometheus collectors and the periodic gauge collector |

## Engineering decisions

- **UUID v7 identifiers, generated by the service.** IDs are not guessable like a sequence, yet stay roughly time-ordered for index locality. The ID exists before the row is written.
- **Explicit SQL with pgx/v5, no ORM.** Every query is visible, parameterised and reviewed with its indexes. Partial updates build their `SET` clause in a pure function that is unit tested.
- **Authorization inside the query.** Repositories receive an `authz.Scope` and filter with `WHERE owner_id = $n OR $isAdmin`. Ownership checks and writes happen in one statement, so there is no read-then-decide window. Moving a task checks the destination project in the same `UPDATE`.
- **Rotating refresh tokens with reuse detection.** Login returns a 15-minute JWT and a 30-day opaque refresh token. Each refresh revokes the presented token and issues the next one in the same family. Presenting an already rotated token means it leaked, so the whole family is revoked. Only the SHA-256 of a refresh token is stored.
- **Password change ends every session.** Updating the password through `PUT /users/{id}` revokes all of that user's refresh tokens.
- **Timing equalisation on login.** When the e-mail is unknown, the password is still compared against a dummy bcrypt hash, so response time does not reveal which e-mails are registered. Both failures return the same `401 invalid_credentials`.
- **Infrastructure errors are never credential errors.** A database outage during login is a `500`, logged in full, not a misleading `401`.
- **Private metrics listener.** `/metrics` is served on `METRICS_PORT` (9091), which Compose does not publish. The public port answers `404` for it.
- **Rate limiting that cannot be spoofed by default.** Login and refresh are throttled per client IP with separate token buckets. Proxy headers (`X-Forwarded-For`, `X-Real-IP`) are honoured only when `TRUST_PROXY_HEADERS=true`.
- **One error envelope everywhere**, including unknown routes (`404 not_found`) and wrong methods (`405 method_not_allowed`).
- **Migrations are a separate step.** `cmd/migrate` runs as a one-shot container before the API starts; the API never changes the schema on boot.

## Quickstart

Run `make help` for every available target.

### Option A: everything in Docker

```bash
make docker-up            # docker compose up -d --build
make smoke                # optional: run the end-to-end checks
```

Compose starts Postgres, runs the migrations in a one-shot container, starts the API once the schema is ready, then Prometheus and Grafana. The API is at `http://localhost:8080`.

```bash
make docker-logs          # follow the API logs
make docker-down          # stop, keep data
make docker-reset         # stop, delete volumes, start fresh
```

### Option B: API on the host, Postgres in Docker

```bash
cp .env.example .env      # set JWT_SECRET to at least 32 characters
make db-up                # start only Postgres
make migrate-up
make run                  # or `make dev` for hot reload with air
```

`make build` produces `bin/api` and `bin/migrate`. Use `make migrate-status` and `make migrate-down` to inspect or roll back the schema.

### Ports

| Port | Service | Published to the host |
|---|---|---|
| 8080 | Public API | yes |
| 9091 | API metrics listener (`/metrics`, `/health`, `/livez`) | no, compose network only |
| 5432 | PostgreSQL | yes |
| 9090 | Prometheus | yes |
| 3000 | Grafana (admin / admin) | yes |

To read the raw exposition by hand:

```bash
docker compose exec prometheus wget -qO- http://api:9091/metrics
```

## Configuration

All configuration is read from the environment. A `.env` file in the working directory is loaded if present; see [.env.example](.env.example).

| Variable | Default | Description |
|---|---|---|
| `PORT` | `8080` | Public API port |
| `METRICS_PORT` | `9091` | Private metrics listener port |
| `APP_ENV` | `local` | `local` logs as text; any other value logs JSON |
| `DATABASE_URL` | required | PostgreSQL connection string |
| `JWT_SECRET` | required | HS256 key, at least 32 characters (`openssl rand -hex 32`) |
| `TRUST_PROXY_HEADERS` | `false` | Take the client IP from `X-Forwarded-For` / `X-Real-IP`. Enable only behind a proxy that overwrites them |
| `TEST_DATABASE_URL` | unset | Enables repository integration tests. Use a dedicated database |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | unset | Optional admin credentials for `scripts/smoke.sh` |

## API reference

All bodies are JSON. IDs are UUIDs. Protected routes require `Authorization: Bearer <access token>`; the scheme is case-insensitive (RFC 6750).

### Endpoints

| Method | Path | Auth | Success | Errors |
|---|---|---|---|---|
| GET | `/health` | public | 200 | 503 database unreachable |
| GET | `/livez` | public | 200 | |
| POST | `/users` | public | 201 + `Location` | 400, 409 |
| POST | `/auth/login` | public | 200 | 400, 401, 429 |
| POST | `/auth/refresh` | public | 200 | 400, 401, 429 |
| POST | `/auth/logout` | public | 204 | 400 |
| GET | `/users` | member | 200 | 400 |
| GET | `/users/{id}` | member | 200 | 400, 404 |
| PUT | `/users/{id}` | self or admin | 200 | 400, 403, 404, 409 |
| DELETE | `/users/{id}` | self or admin | 204 | 400, 403, 404 |
| PATCH | `/users/{id}/role` | admin | 200 | 400, 403, 404 |
| GET | `/projects` | owner or admin | 200 | 400 |
| POST | `/projects` | member | 201 + `Location` | 400 |
| GET | `/projects/{id}` | owner or admin | 200 | 400, 404 |
| PUT | `/projects/{id}` | owner or admin | 200 | 400, 404 |
| DELETE | `/projects/{id}` | owner or admin | 204 | 400, 404 |
| GET | `/tasks` | project owner or admin | 200 | 400 |
| POST | `/tasks` | project owner or admin | 201 + `Location` | 400, 422 |
| GET | `/tasks/{id}` | project owner or admin | 200 | 400, 404 |
| PUT | `/tasks/{id}` | project owner or admin | 200 | 400, 404, 422 |
| DELETE | `/tasks/{id}` | project owner or admin | 204 | 400, 404 |

Every protected route also returns `401` without a valid token.

### Request bodies and validation

| Resource | Create body | Rules |
|---|---|---|
| User | `{"name","email","password"}` | name 1 to 50 characters; plain e-mail address up to 200 characters, stored trimmed and lowercase; password 8 characters to 72 bytes (bcrypt limit). A `role` field is ignored |
| Project | `{"name","description"}` | name 1 to 100 characters; description up to 2000 characters. The caller becomes the owner |
| Task | `{"title","description","project_id","assignee_id"}` | title 1 to 200 characters; description up to 2000; `project_id` required and reachable by the caller; `assignee_id` optional, must be an existing user and not the all-zero UUID. Status starts at `TODO` |
| Role | `{"role"}` | `member` or `admin`. An admin cannot demote themselves |

### Authentication flow

```bash
curl -s -X POST localhost:8080/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"alice@example.com","password":"password123"}'
```

```json
{
  "token": "<JWT, 15 minutes>",
  "refresh_token": "<opaque, 30 days>",
  "expires_in": 900,
  "user_id": "0199f0d8-...",
  "email": "alice@example.com",
  "role": "member"
}
```

- `POST /auth/refresh` with `{"refresh_token": "..."}` returns a new pair and revokes the presented refresh token. Replaying a revoked token revokes the whole family and returns `401`.
- `POST /auth/logout` with `{"refresh_token": "..."}` revokes the token's family. An unknown token still returns `204`; an empty body returns `400`.
- The role in the access token is read from the database on every login and refresh.

### Pagination and filters

`GET /users`, `GET /projects` and `GET /tasks` accept `limit` (up to 200, default 50) and `offset` (0 or more). Responses are plain JSON arrays ordered newest first. A `limit` above 200, a negative `offset` or a non-numeric value returns `400 validation_failed`; a `limit` of 0 or below falls back to the default.

`GET /tasks` also accepts these filters, combinable with each other and with pagination:

| Parameter | Value |
|---|---|
| `project_id` | UUID |
| `assignee_id` | UUID |
| `status` | `TODO`, `IN_PROGRESS` or `DONE` |

### Partial updates

`PUT` updates only the fields present in the body. An empty body `{}` returns `400 no_fields_to_update`. Fields that are not part of the resource are ignored, so `PUT /users/{id}` with `"role": "admin"` changes nothing.

`assignee_id` on `PUT /tasks/{id}` has three states:

| Body | Effect |
|---|---|
| field absent | assignee unchanged |
| `"assignee_id": null` | assignee cleared |
| `"assignee_id": "<uuid>"` | task reassigned |

`PUT /tasks/{id}` also accepts `project_id` to move a task. Both the current and the destination project must be reachable by the caller; otherwise the answer is `404 task_not_found`.

Cascades: deleting a project deletes its tasks; deleting a user deletes their projects (and those projects' tasks) and refresh tokens, and clears them as assignee on other tasks.

### Errors

Every error uses one envelope. `code` is stable and meant for programs; `message` is for humans and never contains SQL or internal details.

```json
{ "error": { "code": "project_not_found", "message": "project not found" } }
```

| Code | Status | Meaning |
|---|---|---|
| `invalid_request` | 400 | Body is not exactly one valid JSON value (trailing data is rejected), or a required auth field is missing |
| `invalid_id` | 400 | Path ID is not a UUID |
| `validation_failed` | 400 | A field or query parameter breaks a rule; the message says which |
| `no_fields_to_update` | 400 | `PUT` with no recognised fields |
| `unauthorized` | 401 | Missing, malformed, expired or invalid access token |
| `invalid_credentials` | 401 | Wrong e-mail or password (indistinguishable on purpose) |
| `invalid_refresh_token` | 401 | Unknown, expired, revoked or reused refresh token |
| `forbidden` | 403 | Authenticated but not allowed (another account, member on an admin route, self-demotion) |
| `not_found` | 404 | No such route |
| `user_not_found` | 404 | No such user |
| `project_not_found` | 404 / 422 | 404 on a project route; 422 when a task references an unreachable project |
| `task_not_found` | 404 | No such task, or not reachable by the caller |
| `method_not_allowed` | 405 | Route exists, method does not |
| `email_already_exists` | 409 | E-mail already registered |
| `assignee_not_found` | 422 | `assignee_id` references no user |
| `rate_limited` | 429 | Too many attempts; honour the `Retry-After` header (seconds) |
| `internal_error` | 500 | Unexpected failure; details are logged server-side with the request ID |

## Permissions and the first admin

There are two roles, `member` (the default) and `admin`.

| Action | Member | Admin |
|---|---|---|
| Read the user list and any user profile | yes | yes |
| Update or delete an account | own only (`403` otherwise) | any |
| Change a role | no (`403`) | any user except demoting themselves |
| Projects and their tasks | own only (`404` otherwise) | all |

**Why 404 for projects and tasks but 403 for users?** A project or task ID that belongs to someone else answers exactly like one that does not exist, so ownership cannot be probed. User IDs are already listed by `GET /users`, so hiding them would gain nothing; `403` is the honest answer there.

Registration and profile updates never accept a role, so the first admin has to be created outside the API:

```bash
make promote-admin EMAIL=you@example.com
```

This runs a parameterised `UPDATE users SET role = 'admin'` inside the Postgres container. The user has to log in again (or refresh) to receive a token carrying the new role. From then on, that admin can promote others with `PATCH /users/{id}/role`.

## Testing

| Command | What it runs |
|---|---|
| `make test` | Unit tests: services with fake repositories, handlers through `httptest`, pure SQL builders, JWT, httpx, config, server routing. No Docker needed |
| `make test-race` | The same with the race detector (needs cgo and a C compiler; without one, run `docker run --rm -v "$PWD":/src -w /src golang:1.27 make test-race`, since the alpine image has no gcc) |
| `make test-integration` | Starts Postgres, creates and migrates the `mini_jira_test` database, and runs every test with `TEST_DATABASE_URL` set, including the repository tests against real SQL. Packages run one at a time (`-p 1`) because they share the database |
| `make test-all` | `vet` + `test-race` + `test-integration` |
| `make coverage` | Integration-enabled run producing `coverage.out` and `coverage.html` |
| `make lint` | `go vet`, `gofmt -s` check, and golangci-lint when installed |
| `make smoke` | `scripts/smoke.sh` against a running API |

Integration tests skip, rather than fail, when `TEST_DATABASE_URL` is unset. They seed their own users and clean up via cascades, but they still write rows, so point them at a dedicated database.

### Smoke test

`scripts/smoke.sh` is an end-to-end check of the running API. It prints `[PASS]`, `[FAIL]`, `[SKIP]` and `[INFO]` lines and exits non-zero on any failure. It covers:

- health and liveness, `/metrics` isolation, and the 404/405 envelopes
- registration, login, refresh rotation, reuse detection and logout
- password-change revocation
- the auth middleware
- users, projects and tasks with all their boundary cases and cross-user isolation
- the `assignee_id` tri-state, task moves, filters and cascades
- the admin flow
- rate limiting with `Retry-After`

```bash
make smoke
BASE_URL=http://staging:8080 ./scripts/smoke.sh
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD=... ./scripts/smoke.sh
```

Without `ADMIN_EMAIL`, the script registers a temporary user, promotes it through `docker exec mini-jira-postgres psql`, runs the admin checks, and deletes the user. `AUTO_ADMIN=0` disables this; `AUTO_ADMIN=1` makes it mandatory. It needs `curl` and either `jq` or `python3`. A login that gets throttled is retried after `Retry-After`, so the script can be run back to back.

## Observability

Logs are structured `slog` records (text locally, JSON otherwise). Each request line carries the method, route pattern, status, duration and request ID.

Prometheus scrapes `api:9091` every 15 seconds. Exported metrics:

| Metric | Type | Labels |
|---|---|---|
| `http_requests_total` | counter | `method`, `endpoint` (route pattern), `status` |
| `http_request_duration_seconds` | histogram | `method`, `endpoint` |
| `db_query_duration_seconds` | histogram | `operation`, `table` |
| `db_connections_active` | gauge | |
| `users_total`, `projects_total`, `tasks_total` | gauge | |
| `tasks_by_status` | gauge | `status` |
| `login_attempts_total` | counter | `result`: `success`, `bad_password`, `unknown_user`, `error`, `refresh`, `bad_refresh`, `refresh_reuse`, `expired_refresh` |

Plus the standard Go runtime and process collectors. Endpoints are labelled with the chi route pattern (`/tasks/{id}`), never the raw path, so cardinality stays bounded. Gauges are refreshed by a background collector every 30 seconds.

Grafana (`http://localhost:3000`, admin / admin) ships with the provisioned dashboard **Mini Jira - API**, which has these panels:

- request rate by route
- 5xx error rate
- p95 latency by route
- p95 database query time by table and operation
- entity counts
- tasks by status
- active database connections
- login attempts by result
- rate-limited (429) requests

## Known limitations and trade-offs

- **Stolen access tokens stay valid for up to 15 minutes.** This applies even after a logout, a password change or a role change. Immediate revocation would need a per-request lookup, which gives up the stateless JWT. Refresh tokens are revoked immediately.
- **Changing the password does not ask for the current password.** A valid access token is enough. Requiring it would be a stronger flow and a contract change.
- **The rate limiter is per process.** With several replicas the effective limit multiplies; a shared store such as Redis would be needed.
- **No JWT key rotation.** Changing `JWT_SECRET` invalidates every access token at once.
- **Every member can read the user list**, including names and e-mails, so that tasks can be assigned. A stricter deployment would restrict this.
- **Any user can be an assignee.** Assigning a task does not give the assignee access to it, because access follows project ownership only.
- **No CORS, no audit log.** Role changes and deletions are visible only in the application logs.
- **Offset pagination.** It is simple and bounded at 200 rows per page, but deep offsets get slower; keyset pagination would scale better.
- **chi's timeout and recoverer middleware** answer `504` and `500` without the JSON envelope in the rare cases they fire.
- **The Go module path is `github.com/abneribeiro`**, without a repository segment, so imports read `github.com/abneribeiro/internal/...`.
